# 题目文件组织方法

## 适用范围

仅负责题面、附件和题目工作区的文件组织。输入可以是用户提供的题目信息、附件或平台页面，不依赖其他技能，不负责解题与正文撰写。

## 工作步骤

1. 首先确保你已经阅读根目录的 AGENTS.md 以及题目相关信息。如果用户输入不包含题目具体信息，则使用可用的浏览器或界面工具获取。大部分比赛平台均使用 Web 应用承载，因此优先读取已打开的相关页面。若找不到题目或失败，调用并发起提问，而不是中止会话。
2. 获取题目标题。如果题目标题包含英语以外的文字，使用音译或翻译的方法转换为全小写字母，视情况而定，目的是让翻译结果看起来易于区分对应。如果直接转换为英语后命名过长，只取关键字。取得的标题不能与现有题目重复。例如：题目名为 `古老的 AI`，则取 `old-ai`；题目名为 `一起探索商城世界吧`，则取 `explore-shop`；题目名为 `万界宝库`，则取 `wanjie`。如果获取标题失败，则从题目意思进行推断。如果题目标题为英文，直接使用该标题，仅需规避文件系统不允许的特殊符号，并将空格替换为符号： `-`。总之，最终获取到的标题应该满足：使用全小写字母，不包含空格，词语分割统一使用 `-`，不包含文件系统不允许的特殊符号。
3. 确定解题顺序并建立题目专属工作区。该顺序以落盘目录为准。顺序采用 0-base。列出工作区根目录下的内容。如果你看到根目录下不包含文件夹，则从 00 开始创建文件夹。如 `00-wanjie`，此后创建新的文件夹时，则使用 `01-explore-shop`，`02-old-ai`，以此类推。如果你看到已经包含了一些文件夹，先确认文件夹性质。如果不是题目工作区文件夹，忽略它们。如果是题目工作区文件夹，则先确认命名是否符合前述规则。已有目录不符合命名规则时默认保持原样，仅为新题选择未使用的顺序前缀；用户要求重命名时再整理。
4. 题目文件夹中创建 `WRITEUP.md`（仅准备文件，不撰写正文），然后继续新建文件夹，包含 `challenge`，`solve`。其中 `challenge` 文件夹用于存储 `timm.txt`（题面文字信息及线索，如有则创建），以及题目提供的附件（如有，保留原始附件并解压；核心文件可直接释放至 `challenge`，但保留具有语义或相对路径依赖的子目录，避免覆盖重名文件。）。无题面或附件需要落盘时，不必新建 `challenge`，已存在的目录无需删除。`solve` 用于存放解题时使用的脚本；具体脚本及 WRITEUP 正文由对应任务处理。

## 保留与复现

- 已有本题目录默认沿用；除非用户要求整理命名，不为满足编号规则重命名已有题目目录。
- 保留原始压缩包和题面；解压时保留影响含义或相对路径的目录结构，避免展平导致重名覆盖。核心文件可以直接置于 `challenge`，但不以整齐为由破坏附件结构。
- 记录附件来源及必要的哈希。分析生成物放入 `.draft`，脚本放入 `solve`；原始附件不作为输出文件覆盖。
- 无需为目录规范而清理已有空目录；准备与检查保持简短，不替代解题实验。

## 边界

不允许为了实现目标文件目录组织结构而删除任何已存在的文件。允许移动文件，但绝不允许执行对文件的删除操作。

## 完成标准

列出本题目录树，检查题面、原始附件及脚本位置，避免遍历无关题目。需要结构示例时参考 `./references`；独立解题测试时仅参考目录结构，不读取示例题解或脚本中的答案。
