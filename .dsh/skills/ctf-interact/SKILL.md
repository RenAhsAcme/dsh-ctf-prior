# 远程交互与连续闯关

## 适用范围

负责有提示符、查询预算、随机实例或失败重置的题目的通信与运行。输入为题面协议、源码、服务地址或已录制的收发；输出为可复用通信层、模拟或回放程序及运行证据。不依赖其他技能，不要求固定目录或记录格式。

## 工作步骤

根据实际协议选用以下方法，不把一次题目的参数当作通用限制。

### 稳定通信

- 用一次短连接记录原始收发、提示符、换行、查询计数及成功/失败后的状态。题面没有源码时，先记录实际协议，再选择数学实验。
- 提取一个共享通信层供 probe、模拟对接和 solver 使用；解析修复在此完成，避免复制成多份脚本后再次引入同一错误。
- TCP 是字节流：消息可能拆包或粘包，提示符可能没有换行。按协议标记/完整行读取，保留未消费的缓冲区；不要用一次 recv 或任意字节长度作为消息边界。
- 尚无可靠通信层时，可复用本技能的 [scripts/buffered_io.py](scripts/buffered_io.py)：只提供带总超时的字节流读取，不包含连接地址、题目协议或重试策略；已有可靠实现则沿用。
- 正常空行、超时和 EOF 分别处理。超时不能返回伪造的空行/None，EOF 不能无限重试；未收到目标标记时，报告当前状态与原始缓冲区，避免拿半截 banner 当整数或把提示符当回答。
- 对录制片段做离线回放：改变分块边界，覆盖空行、无换行提示符、None、拒绝、重置、EOF 和超时。先通过解析检查，再用一关真实交互验证接口。
- 不变量尽早检查，例如输入范围、查询预算、返回根的平方同余、因子乘积。若根不满足同余，先查传输、解析与数学实现，不据此推断 oracle 特性。
- 阶段结束以成功/失败标记、下一关提示或 EOF 驱动，不用固定 sleep 或永远为假的等待条件代替。已知服务限速或输出延迟时保留必要等待，并单独测量。
- 终局必须在完整结果边界停止：`flag{` 等前缀只表明结果开始，不能当作完整结果。继续读取到闭合格式、完整行或 EOF；EOF 前收到的字节仍是有效数据，先解析与落盘，再决定是否重连。连接正常关闭本身不表示解题失败。
- 完整运行前回放末关路径：成功文本与结果在同一数据块、结果任意分块后关闭、失败重置后下一关、超时后保留半包。重复前缀出现时，不能吞掉未完成结果或沿用旧关卡状态。

### 本地模拟与策略比较

- 将策略写成接受 `ask(x)` 回调的纯函数，与 socket、日志和界面操作分离。可在本地复现服务数学语义时，远程只确认语义和少量集成行为，大样本策略比较在本地进行。
- 模拟器保持查询上限、输入范围和 oracle 选根规则。用已知因子等独立真值核对返回结果，并在小实例上穷举校验，避免策略和模拟器共用错误实现而互相证明。
- 保存失败实例的实际参数、询问轨迹、策略版本和查询计数；随机种子与试验序号可辅助定位，不能代替实例。先修复失败样本，再比较固定输入集；最后用新样本检查泛化。
- 缓存本地实例及与策略无关的昂贵计算。比较多个策略时使用同一实例，不为每个参数组合重新生成素数或整套随机输入。
- 有限预算的 oracle 查询前，先使用可本地计算的必要条件过滤无效输入；检查已知等价类、重复查询及平凡回答。加入复杂信念规划前，先测量简单筛选和已有关系能否解决目标失败。
- 更换策略时同时比较失败率、耗时和查询成本。某些询问共享未知量时，其结果可能相关；将单次失败概率连乘只当启发式评分，不能写成已证明的整轮失败率。
- 同一策略的重复大样本运行需要明确目的，例如估计置信区间或检查新样本；不要在小改动尚未修复目标失败前反复执行全量模拟。

### 连续闯关成本

- 先确认失败后是原关重试、回到首关、断连还是保留进度。评估的是取得最终结果的成本，而不只是单关询问数或单次速度。
- 若各关近似独立、失败率相同且为 q，L 关整轮成功率约为 `(1-q)^L`；有相关性或关卡分布差异时使用对应模型或整轮模拟。区分理论结果、经验估计和未验证假设。
- 零失败的小样本不代表零风险。独立同分布的 m 次试验零失败时，单次失败率的单侧 95% 上界约为 `3/m`；按所需整轮成功率决定样本量，不强制所有题目跑大样本。
- 分别测量本地计算、服务响应、客户端主动等待及重试成本。优化前后使用相同实例或录制输入；不要把服务波动当作算法加速。
- 当短程远程验证通过、整轮成功率及成本可接受时开始完整运行。进一步改进应针对已保存失败或明确瓶颈；没有收益证据时沿用最佳版本。
- 将继续调参的耗时与当前策略预期取得结果的时间比较。若每关独立、成功率 s、每关平均成本 t，失败即重置，则 L 连胜的期望成本约为 `t*(1-s**L)/((1-s)*s**L)`（s=1 时为 L*t）；额外连接成本与非恒定关卡单独处理。调参预计节约不足以覆盖验证成本时，先运行最佳已验证版本，而不是追求接近零失败。

### 长任务运行

- 启动长任务后记录任务 ID、日志路径、版本和预期耗时；由脚本持续落盘进度。运行中不要改动该任务使用的源码版本，比较新版本时保留独立副本。
- 等待期间可整理已有证据、检查失败样本、准备题解结构。按任务预计耗时检查新增进度，避免连续读相同日志，也避免一次阻塞数分钟而无法响应用户。
- 首次长跑即记录每关状态、失败参数和最终原始输出；不要为增加日志中断可能已接近完成的任务。错误或超时后先检查日志、未消费缓冲区和已保存结果，确认尚未完成才重试。
- 未确认服务允许并发会话、会话互不影响且有实际收益前，使用单个远程完整任务。需要并行时优先并行独立的本地分析；串行化或资源竞争出现后停止额外会话。

## 边界

- 服务访问与重试遵循用户授权范围；协议观测、算法模拟和实际服务结果分别记录。
- 不负责平台界面操作、附件整理或正式题解；必要信息缺失时明确指出，不要求调用其他技能补齐。

## 完成标准

通信层正确处理已观察到的协议状态；模拟或回放覆盖本次修改相关的输入与故障；运行记录能区分协议错误、策略失败、重置和完成。仅有本地验证时注明尚未通过远程验证，不把短程成功等同于完整闯关成功。
